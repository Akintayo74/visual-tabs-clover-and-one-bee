# Visual Memory — Plan

*Working title. Rename freely.*

## Mission

**Everything that inspires you is kept exactly as it looked, and you find it again by describing what you saw.**

A browser extension for designers who hoard inspiration in open tabs. One keystroke saves a site as it looked. Every new tab shows a visual wall of saved sites, searchable by vague, memory-style descriptions.

## Why this exists

Our first user is a web designer who keeps dozens of tabs open, some for over two months, because he's afraid of losing them. What we learned from him:

- **Losing them is painful.** When his browser crashes, he *always* restores his tabs.
- **They're a long-term reference library**, not a to-read list.
- **They're mostly inspiration.**
- **He recalls sites by how they looked and how they were built**, not by name or content. A real query of his: *"a one-page site with only one section with large text on it. Each text takes you to a particular page."*

Existing tab savers and bookmark managers search text (titles, URLs, page content). They fail this kind of recall.

## The bar: it must work seamlessly

Visual design can be rough in v1 and will be iterated. Reliability and search quality cannot. The product only works if he trusts it enough to close his tabs. Concretely:

1. **Saving never fails silently and never loses data.** Feedback within ~300ms. The save is stored locally first, then uploaded and processed in a background queue with retries. Works offline and catches up later.
2. **The new tab appears instantly.** It renders from a local cache (IndexedDB) in under ~100ms, then syncs in the background. Grid is virtualized and images lazy-load.
3. **Search finds the right site in the first few results for memory-style queries.** Measured with real queries from our user (see Phase 4).
4. **Every state is visible.** Each card shows whether it's processing, ready, or failed (with retry).
5. **Unsupported pages fail gracefully.** `chrome://` pages, the Chrome Web Store, PDFs, etc. get a clear "can't save this page" message.
6. **He can always get his data out.** One-click export of everything.

## Key decisions (already made)

- **Manual marking only.** Nothing is captured unless he presses the shortcut. Solves privacy and noise.
- **Shortcuts:** `Save` and `Save & close tab`. (Exact keys TBD; avoid conflicts with common browser shortcuts.)
- **Screenshot = visible viewport** via `chrome.tabs.captureVisibleTab`. No full-page capture in v1. Keep original aspect ratio, never crop.
- **Page fingerprint:** at save time, a content script extracts structural facts the screenshot can't show (see below). This is essential for queries like the one above.
- **Storage:** Supabase is the source of truth (Postgres + pgvector + Storage + Auth + Edge Functions). IndexedDB is the local cache the new tab reads from. API keys live only in Edge Functions, never in the extension.
- **Models** (verify current model IDs and API shapes against official docs before implementing):
  - Description + recall phrases: **Claude Sonnet 5.5** (`claude-sonnet-5-5`) via the Anthropic API. Volume is low, so quality wins.
  - Embeddings: **Voyage `voyage-multimodal-3.5`**, embedding the screenshot and the generated text together as one interleaved input.
  - Reranking: **Voyage `rerank-2.5`**.
  - Keyword search: Postgres full-text search.

## Data captured per save

### Screenshot versions
| Version | Width | Format | Approx size | Use |
|---|---|---|---|---|
| Full | 2400px | WebP ~q80 | 250–500 KB | Detail view |
| Card | 960px | WebP ~q75 | 60–120 KB | Grid |
| Model input | ~1500px | WebP/JPEG | — | Sent to Claude and Voyage, not stored |

### Page fingerprint (content script)
- URL, canonical URL, title, site name, favicon
- Page height in viewport-heights; count of sections; presence of header/nav/footer
- Largest text elements on the page (text, font size, whether each is a link and where it points)
- Link count; internal vs external
- Fonts in use (headings vs body)
- Colour palette (also derivable from the screenshot)
- Signals: WebGL/canvas, video backgrounds, scroll-driven animation, common animation/3D libraries detected
- Viewport size and device pixel ratio

### Generated by the model
- **Description**: a designer's description covering layout, structure, typography, colour, mood, interaction, and type of site
- **Recall phrases**: 5–8 short descriptions written the way someone would describe the site *from memory* (e.g. "a one-page site that's just huge typographic links to other pages"). This is the single biggest lever for search quality.
- **Tags**: short style/structure/industry tags

## Schema (starting point)

```sql
saves (
  id uuid primary key,
  user_id uuid references auth.users,
  url text, canonical_url text, title text, site_name text, favicon_url text,
  created_at timestamptz, updated_at timestamptz,
  status text check (status in ('pending','processing','ready','failed')),
  error text,
  image_full_path text, image_card_path text, width int, height int,
  fingerprint jsonb,
  description text, recall_phrases text[], tags text[],
  palette text[], fonts text[],
  note text,
  prompt_version int,
  embedding vector(1024),
  search_tsv tsvector  -- generated from title, site_name, description, recall_phrases, tags, fonts, note
)

search_events (
  id uuid primary key, user_id uuid, query text,
  clicked_save_id uuid, rank int, created_at timestamptz
)
```

Row-level security on everything. Re-saving the same page (matched on its normalised page URL) updates the existing save with a new snapshot rather than creating a duplicate. The canonical URL is stored but not used for matching, because some sites point every page's canonical at their homepage (decided 2026-10-20, Phase 2).

## Search pipeline

1. **Instant layer (local):** as he types, fuzzy keyword search over the cached saves in IndexedDB shows results immediately.
2. **Semantic layer (Edge Function `search`):** on pause/Enter, embed the query with `voyage-multimodal-3.5` (query mode) → vector search (top ~50) + Postgres full-text search (top ~50) → merge with reciprocal rank fusion → rerank top ~30 with `rerank-2.5` over description + recall phrases + tags → return ranked IDs.
3. Results smoothly replace the instant layer without the grid jumping around.
4. Log query + clicked result to `search_events` (for future tuning).

## New-tab page (functional, not final design)

- Search bar at top, autofocused.
- Grid of large cards: 3 columns at ~1440px wide, 4 on larger screens; density toggle (2/3/4).
- Each card: screenshot, favicon, site name, domain; processing/failed state when relevant.
- Click → detail view: full screenshot, description, fonts, palette, note, "Open site", "More like this", delete.
- Keyboard: arrows to move, Enter to open, Esc to close detail, `/` to focus search.
- Default sort: most recent.

## Phases

Each phase ends with something usable and a short checklist that must pass before moving on.

### Phase 0 — Foundations
- Monorepo: `extension/` (Manifest V3, TypeScript; choose a modern extension framework such as WXT or Vite + CRXJS and justify the choice) and `supabase/` (migrations, Edge Functions).
- Lint, format, typecheck, unit test setup.
- README with local dev and how to load the unpacked extension.

**Done when:** the extension loads in Chrome, overrides the new tab with a placeholder, and `supabase start` runs locally.

### Phase 1 — Capture and the local wall (no AI, no cloud)
- Shortcuts for Save and Save & close; toolbar button as alternative.
- Screenshot capture → full + card WebP versions.
- Content script fingerprint extraction.
- Store in IndexedDB; dedupe by page URL (originally canonical URL; changed in Phase 2).
- New-tab wall: virtualized grid, detail view, open site, delete, keyboard nav.
- Graceful handling of unsupported pages.

**Done when:** saving 20 varied real sites works every time, the toast appears within ~300ms, and the new tab renders the wall near-instantly.

### Phase 2 — Import open tabs
- "Import my open tabs" flow: steps through each tab in the window, activates it, waits for load, captures, saves. Progress UI, cancel, skips unsupported pages, respects capture rate limits, restores the originally active tab.
- Option to close tabs after successful import.

**Done when:** importing a window of 50 real tabs completes reliably and the user can close them all. This also gives us a real dataset for Phase 4.

### Phase 3 — Durable storage and sync
- Supabase schema, RLS, Storage buckets.
- Auth (email magic link or one-time code is enough for now).
- Background upload queue with retries and backoff; offline support; status per save.
- Sync down to the local cache on a new device / fresh install.
- One-click export (JSON + images, zipped).

**Done when:** saves survive uninstall/reinstall, work offline and upload later, and a second browser shows the same wall.

### Phase 4 — Understanding and search
- Edge Function `process-save`: Claude description + recall phrases + tags (versioned prompt), Voyage embedding, write back, update status. Idempotent and retryable.
- "Reprocess all" job for when prompts change.
- Edge Function `search` as described above; instant local layer in the UI.
- **Evaluation harness:** `eval/queries.json` with real queries from our user mapped to the save(s) he means; a script reports hit@1, hit@3, hit@5. Iterate on prompts and fingerprint until targets are met.

**Done when:** on his real queries, the right site is #1 at least ~70% of the time and in the top 5 at least ~90%, and his example query above finds the right site.

### Phase 5 — Polish for the two-week trial
- "More like this" (nearest neighbours by embedding).
- Filters: colour, font, date.
- Personal note per save, included in search.
- Density toggle; empty states; error states reviewed.
- Package the extension for easy install by the trial user.

**Done when:** our user can use it daily without help.

## Trial success metrics
- His open tab count drops and stays down.
- He finds what he's looking for in the first one or two searches.
- He never loses a save.

## Out of scope for v1
Automatic capture, full-page screenshots, collections, sharing, multi-user features, browsers other than Chrome/Chromium, auto-closing old tabs, final visual design.
